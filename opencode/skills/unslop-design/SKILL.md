# Unslop Design

Design from the product's purpose, content, users, and constraints. Do not begin from a fashionable template.

## Before Designing

State or infer four things: primary user, primary task, desired character, and technical constraints. If a missing answer would materially change the result, ask one short question.

Choose one clear visual direction that fits those facts. Reuse an existing product's design language when one exists.

## Rules

- Make hierarchy come from typography, spacing, alignment, scale, and contrast before decoration.
- Let content determine layout. Do not put every section in a floating rounded card.
- Use a restrained type scale and spacing system. Keep dense tools dense and expressive pages expressive.
- Give important actions clear labels and priority. Do not turn every control into a pill.
- Use color to communicate brand, state, grouping, or emphasis. Maintain readable contrast.
- Choose typefaces for the product's character and reading needs, not novelty alone.
- Use real product language and plausible content. Avoid generic startup copy and invented metrics.
- Keep navigation and interaction familiar unless deviation improves the task.
- Design empty, loading, error, focus, hover, disabled, and responsive states.
- Preserve accessibility, keyboard use, semantic structure, and reduced-motion preferences.
- Prefer a few deliberate details over many effects. Every flourish must support character or function.

## Defaults To Challenge

Do not automatically use purple or blue gradients, aurora blobs, glassmorphism, glowing borders,
huge gradient headlines, excessive rounded rectangles, card grids, pill-shaped controls, floating
dashboard panels, decorative charts, generic hero layouts, centered text everywhere, or uniform
icon-and-text feature rows.

These are not banned. Use one when the product context supports it, then make it deliberate:

- A gradient should express depth, light, progression, data, or brand, not fill empty space.
- Purple should come from brand or subject matter, not from an assumed "tech" aesthetic.
- A card should represent a distinct object or actionable group, not merely contain content.
- A pill should represent a compact status, filter, tag, or toggle, not any button.
- Glass effects need a meaningful layered surface and must remain legible.
- Large display type should earn its space through message and composition.

## Final Check

1. Can the primary task be found and completed quickly?
2. Does the interface fit this product, or could its logo be swapped with any startup?
3. Is each container, color, radius, effect, and animation doing a job?
4. Does it work at narrow and wide widths with realistic content?
5. Remove one decorative layer. Keep it removed unless the design became less clear or less distinct.
